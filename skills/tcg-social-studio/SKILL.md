# 需要・訴求・参考の再現から投稿一式を作る

版：2.8.0／2026-11-13。**案件の前提 → 需要 → 買う理由 → してほしい行動 → 参考全体の分解 → 制作 → 並べて検品**の順で進める。19型は目的の分類で、19個の完成デザインではない。

GitHubで管理する配布版はこのフォルダ。古い配布ZIP・別フォルダ・相手のPCは自動更新されない。整備依頼では改修・検証・配布可能な一式まで行い、新作広告や公開は依頼範囲に合わせる。通常の「作って」は分析で止めず完成画像／MP4・英日本文まで作る。公開・予約・送信は別の明示依頼で行う。

## 1. 案件の前提を確認する

独立した `$tcg-social-intake`（同じskillsフォルダ内の `tcg-social-intake/SKILL.md`）を必読・実行する。案件・対象客・市場・目的・行動・企画数・操作範囲を根拠付きで整理し、制作フォルダに `01_intake.md`・`01_intake.json`・検査結果を残す。必要な既存資料を読んで埋め、既知の情報を聞き直さない。

「1つ作って」は1企画。工程ごとの依頼は第1工程で止め、前提と仮置きを見せる。通常の全制作依頼なら前提記録の検査と内容照合で `ready_for_selection: true` を確認して第2工程へ進む。記録なし・必須条件未決のまま商品を選ばない。

共通試作と特定店の制作、別途進行中の専用スキルを混同しない。閲覧・編集を禁止された表はその範囲で対象外にし、既存の「管理表を読む／更新する」手順より最新指示を優先する。独立スキルが未配置なら配布セットの両フォルダを配置し、古い入口だけで済ませない。

[事業情報](templates/business-brief.md)は入力資料として使えるが、第1工程の記録に代えない。[利用環境](references/setup.md)の接続・取得・生成・保存・レンダリングは各実行直前に確認する。説明書の存在を動作確認済みとしない。

参考の取得は第3〜4工程で行う。参考IDはアクセスを許された台帳の実際の行と元投稿URLを照合し、連番や過去メモだけで推測しない。禁止された台帳がなくても、今回指定された元URLや原素材で特定できれば進められる。参考はMuse側で用意し、[素材の受け渡し](references/media-input.md)に従って全原本を取り込む。保存済み原本を優先し、不足を明示する。ブラウザー操作禁止の指定は守る。

**台帳・利用者が指定した参考は、全ページ・全編の忠実な再現が既定。** 雰囲気だけを借りるのはその指定があるとき。色・文章だけ替えた共通テンプレートを完成にしない。参考にあるカット・点滅・再登場は古い連続表示の一般則より優先し、参考にない商品リセットは入れない。制作指示には実測表の値を入れ、内容の差し替えをレイアウト再現の免除にしない。要素が元より少ないときは枠に合わせて拡大し余白を均す。詳しくは再現仕様の「実測から外さないための決め」。

## 2. 需要に基づいて商品を選ぶ

[需要と選定](references/demand-selection.md)を必読。相場一覧・LINE価格表は仕入れ条件を確かめる入力で、需要や投稿候補のランキングではない。

- 現在の同一商品・言語・状態・対象市場の購買需要を確認。安いだけ、高額、有名キャラ、素材があるだけでは採らない。
- 需要の主指標は価格の動きではなく販売件数（流動性）。確認先と手順は[需要と選定](references/demand-selection.md)の「需要調査の実務」に従い、BOX・PSA 10・ARバルクの各カテゴリで数値と出典を残す。取扱いカテゴリはシングルに限らず、未開封BOX・PSA鑑定品・ARバルクも主力として同じ確認を通す。
- スニダン・Amazon日本・eBay・TCGplayerで、観測した指標と取得できない項目を残す。国内需要と対象国の需要を混ぜない。
- 同じ客向けの候補と比較し、なぜ今この商品かを書く。掲載された成約サンプル数を市場全体の月販にしない。
- 案数未指定は異なる3企画を目標。弱い案で数を埋めない。明示された案数・形式を優先し、カルーセル3枚を3企画に数えない。
- 「この投稿案を作った理由」「この投稿案でのゴール」を制作記録へ。管理表の更新も依頼されていれば該当見出しへ記入し読み戻す。

根拠不足なら他候補を調べる。「注目候補」「Japan market watch」への言い換えだけで販売目的の案を通さない。

## 3. 参考の文字を分析し、自分の提案を作る

[訴求の分析と文章](references/purchase-intent.md)を必読。画面内文字・音声・投稿本文・導線を分けて読み、一本の流れとして照合する。

分析レポートは実画像／時刻、原文、意味、客の欲求、利益と根拠、購入をためらう理由への答え、行動、自社に使う条件を対応させる。元投稿の事実・分析上の推測・自社への提案を分ける。投稿者の主張を確認済みの市場事実としない。

比較には[価格比較](references/price-comparison.md)も適用。同じ商品の国内外、言語別、同一商品の時点差を混ぜない。日本語版の優位が小さい・費用で消える・需要不明なら「割安な仕入れチャンス」にしない。差額と利益は別。

画像上部・動画冒頭には「何の、どんな買い得／買う理由か」が分かる短い見出し。本文には行動を一文で書く。DMは何を送ると何が分かるか、リンクはどのページで何を見てほしいかまで示す。

## 4. 全参考を制作できる単位へ分解

[全ページ・全編の再現仕様](references/reference-reproduction.md)を必読。

- カルーセルは受け取った全画像を元の順番どおり保存し、全画像の文字を読む。先頭1枚・サムネイル・本文だけは取得途中。元の枚数・各ページの役割・レイアウト変化・締めを保持する。
- 動画は全編を取得し、映像カット、字幕、商品／カメラの動き、効果、音を別トラックで記録。Cutmatch方式の毎フレーム差分・動き推定・境界前後確認を補助に使う。字幕の変化を自動的にカットへ変換しない。
- `scripts/analyze_reference_video.py` は候補境界と時刻付き一覧を作る。候補は自動確定しない。文字・効果の出入りは実画像を開いて確定する。
- [分解表](templates/reference-breakdown.example.json)へ原文、座標・寸法・書体・縁取り・背景、開始／終了フレーム、キーフレーム、置換素材を記録。音が聞けなければ音の検証は未完了。
- 全参考の取得・文字確認・時刻の確定前に汎用HTMLへ文章を流し込んで完成させない。

## 5. 商品と表現・本文を制作

[制作手順](references/production.md)と[参考照合](references/reference-design.md)を使う。商品番号・版・状態を確認した原画像を保持する。画像生成の既定方針はgpt-image-2。商品を再描画して番号や絵柄を変えない。背景・装飾は生成でき、文字・商品・数字は確定素材で重ねる。

参考に合わせてHTML／動画編集環境を選ぶ。`templates/story/`と`templates/reel/`は動作確認用で、忠実再現にそのまま使わない。静止画参考に動きを足した場合は動画化案として区別する。

`create_story.py`は未完成の`production-contract.json`も作る。`build_from_recipe.py`は[作り方カード](references/recipe-cards.md)から元の枚数・尺・配置・キーフレームを保持した編集用HTMLを作る。どちらも需要・デザインの合格を自動付与しない。

原書体がない、人物や倉庫を商品へ置換する等は差分として記録。近似を完全一致としない。競合の店名・在庫・発送日・実績は自社の確認済み情報に置き換える。取得素材や顧客情報は利用者の制作フォルダへ保存し、スキル本体へ混ぜない。

### 動画（リール）は技術を全て使う

動画は「作れるか」の確認用に水準を下げない。フェードとズームだけの素朴な作りは未完成として扱う。参考を超えるには次を全て入れる（根拠：2026-11-13のREF-054／REF-007実測と、リール本制作v1への利用者是正を経たv2）。

- **フォント**：衝撃テロップには太い縦長ゴシック（Anton等）、品格の行には明朝・セリフ体を、実ファイルを `@font-face` で読み込んで使う。既定書体（Arial等）で済ませない。撮影時にフォントが実際に当たっているか確認する（`document.fonts.check` 等）。元の書体が特定できない場合は差分として明示する。
- **テロップ**：静止した文字を置かない。プレートのワイプイン、数字の叩き込み（拡大→等倍＋オーバーシュート）、語単位のポップイン、字間のアニメーション、カード名・型番などの情報テロップ（白文字＋黒縁取り）を使う。
- **カット割**：参考動画のカット位置を実測してから設計する。場面を細かく割り、カットごとに役割を持たせる（マクロの寄りで始める、白フラッシュ等の遷移、終盤の短いマイクロカットでリズムを作る）。
- **効果**：全ての動きにイージングを付け、直線的な動きにしない。山場では画面シェイク、ホロのきらめき（星の瞬き）、光の帯（screenブレンド）、ビネット、仕上げの色調補正を使う。
- **商品の見せ方**：参考は「商品が画面いっぱい、文字は重ね」。カードは全幅（目安85%以上）を基本とし、余白に文字を置く構図にしない。
- **音**：使えるBGM音源が無い場合でも、効果音（切り替え・山場・きらめき）だけは合成して入れ、無音で出さない。音声トラックの有無をffprobeで確認する。BGMが無いことは納品時に明示する。
- **超える軸と及ばない軸**：解像度・書体・テロップの演出・情報の正確さ（出典と注記）では参考を超えにいく。静止画ベースでは実写ホロの鋭い反射と実在庫の量には届かない。この差分は納品時に先に報告する。
- **検品**：指定時刻のフレームを抜いて目視する。フラッシュやきらめき等の瞬間の効果は、その時刻のフレームで確認する。前版・参考との同条件の並置比較を付ける。
- **テンポ**：核心の情報（価格など）は場面の開始から1秒以内に出す。導入のタイトルは1秒以内に完成させる。1枚の紹介は約2秒を目安とし、情報が出た後にゆっくりしたズームだけで間を持たせない。どの瞬間も何かが動いている状態にし、静止時間を作らない。終盤に短いマイクロカット（0.5秒前後）を入れてリズムの山を作る。尺は内容が決める。同じ内容なら短い方を選ぶ（承認実績：ラインナップ4枚を19秒→12秒に詰めた版）。
- **視認性**：テロップは背景の一番 busy な箇所でも一目で読めることを、検品フレームで必ず確認する。busy な商品絵の上に重ねる文字は、太い書体（Anton等の極太）を既定とし、白＋太い黒縁取り＋影＋必要なら暗いスクリムを併用、不透明度は1.0にする。細いセリフ体での重ねは、スクリムを足しても不足だった（REF-054型の見本で2度是正）。参考の文字が控えめでも、自社版では読めることを優先し、その差分として記録する。
- **型ごとにデザインを変える**：型が違えばデザイン言語（背景、書体、プレートの有無、切り替え方、音の使い方）も変える。同じ文法の色替えは「別の動画」にしない。共通にしてよいのは締めのブランド要素（ハンドルと合言葉の出し方）だけ。両極の実例：強い型（黒背景・太いゴシック・叩き込み・シェイク）と静かな型（クリーム背景・明朝・フェードと罫線だけ）。

### 本文と導線を完成

[投稿文と納品](references/copy-delivery.md)に従い、Instagram／Facebookの英語本文と全文日本語訳を作る。媒体指定を優先。主語・数字・確度・約束を英日で変えない。

「具体的な提案 → 証拠 → 買い手の得 → 次の行動」をつなぐ。未確定の送料・供給数・発送日を約束しないDM相談投稿は、それらが不明でも進められる。訴求の中心の価格差や需要が不明なまま進めることとは区別する。

定型の価格免責文や出典を投稿面へ自動追加しない。必要な通貨・言語・状態・単位・比較日付は主文や項目で示し、出典・確認日時・費用条件は内部記録へ保持する。

## 6. 不合格を残さず検品

[完成判定](references/acceptance.md)に従う。需要、提案と行動、全参考の網羅、再現、技術確認を別々に検査。一つでも不足ならその企画を直す。

```powershell
python scripts/validate_production.py 制作フォルダ/production-contract.json --out 制作フォルダ/checks/acceptance.json
```

この検査は根拠ファイル・全枚対応・時刻・未解決差分の確認補助。内容の真偽や美しさは自動採点しない。完成PNG／MP4を開き、全ページ対照または同期した全編比較で目視する。境界は前後1フレーム、動きは始点・中間・終点を照合する。

## 7. 投稿一式を納品

前提記録、分析レポート、選定根拠、分解表、原素材、編集元、全完成画像／MP4、英日本文、比較ページ、検品結果を納品し、`00_投稿一式.md`を入口にする。「変更・制作」「確認結果」「未完了・反映していない配布先」を区別し、技術検査を品質や集客効果の実証としない。
