# 毎日ネタを出し、案を作り、人が選んだものを投稿する

版：5.3.0／2026-11-22。

このスキルの仕事は2つある。どちらも、人に頼まれるのを待たずに定期実行で動く。

| いつ | すること | 読むもの |
|---|---|---|
| 毎日1回、`client.json` の `create_time` の時刻（または「今日の投稿を作って」と頼まれたとき） | その日の動きを調べてネタを出し、選ばれた案を完成させ、表の「投稿」タブに1案1行で書く（下の「毎日の流れ」） | この文書 |
| `client.json` の `post_times` の各時刻 | 表を見て、「投稿OK」にチェックが付いた行を1本投稿し、結果を表に書く | [投稿する](references/publish.md) |

**「投稿OK」のチェックは、人による投稿の許可。** チェックが付いた行は、改めて確かめずに自動で投稿する。チェックの無い行は投稿しない。

投稿の目的は、見た人に「この店に聞けば手に入りそうだ」と思ってもらい、**価格と頼み方を聞く見積もりのDM**をもらうこと。再生数やいいねの多さは目的にしない。そのために、どの案も、最初の画面で「誰向け・何が・いくら・どう頼むか」が分かるように作る。その日に在庫があるかどうかは、商品を選ぶ条件にしない。

## 進め方の決まり

- **人に聞くのは、ネタを選んでもらう1回だけ**（`client.json` の `plan_approval` が `chat` のとき。[商品を決める](references/research.md)の4）。それ以外は途中で質問しない。分からないことは調べて自分で決め、決めた理由を表の「選んだ理由」に書く。決められない案は捨てて、別の商品か別の参考で作り直す。
- **止まるのは、[client.json](client.json) の必須欄が空のときと、`sheet_url` がひな形の表のままのときだけ。** 毎回最初に `node scripts/check_client.mjs` を実行し、`[ERROR]` が出たら、出た欄をそのまま伝えて終わる。`[TODO]`（表か共有フォルダのアドレスが空）は止まる理由にしない。[START_HERE.md](START_HERE.md) の「表と共有フォルダを作る」のとおりに自分で作り、アドレスを `client.json` に書いて続ける。道具が動かないときは止まらず、[止まったときの早見表](references/troubleshooting.md)で直して続ける。
- **人がするのは、ネタを選ぶことと、チェックを入れること。** 「投稿OK」の欄は人だけが触る。表の「聞かれた商品」タブも人が書く（DMなどで聞かれた商品。空でもよい）。
- **素材は自分でそろえる。** 参考投稿は保存済みの原本（`reference-originals/`）を先に使い、無いものだけ自分で開いて保存する。商品画像は自分で取りに行く。他人の出品写真は使わない。

## 最初に読むもの

[client.json](client.json)。店名・アカウント・スプレッドシートのアドレス・保存先など、**渡す相手ごとに違うものはここにだけ**書いてある。

`client.json` のうち、作り方を変える欄は次のとおり。

| 欄 | 意味 |
|---|---|
| `price_display` | `quote` なら、日付を付けた自分の見積もり価格を出す。`market`（または空）なら、市場の相場だけを出し、自分の売値は書かない。計算は[文章](references/copy.md)の「価格の出し方」 |
| `contact.keyword` | DMで送ってもらう合言葉。毎回これを使う。空なら `PRICE LIST` |
| `footage_folder` | その相手が撮った実写の映像・写真の置き場。空なら、実写なしで作る |
| `plan_approval` | `chat` なら、作る前にネタをチャットに出し、人が選んだものだけ作る。`off`（または空）なら、人に聞かずに `daily_set` の数だけ自分で選んで作る |
| `plan_count` | 出すネタの数。空なら5 |
| `games` | 扱うカードゲーム。空なら `["pokemon"]`。ワンピースカードも扱うなら `["pokemon","onepiece"]` |
| `focus_products` | その店が主に売る商品の種類（例：`["シングル","PSA","ARバルク"]`）。書いてあれば、ネタの半分以上をその種類にする。`BOX` が入っていなければ、未開封BOXは相場の話題として1つまで。空なら、今までどおり未開封BOXとまとめ売りを半分以上にする |

商品の種類・色は `client.json` に書かない。毎回決めて、表のその行に残す。

| 毎回決めるもの | 決め方 |
|---|---|
| 商品と商品の種類 | 毎日、その日の動き（発売の予定・同業者の投稿・海外で売れたもの・国内の値動き・聞かれた商品）を調べて決める。 |
| 誰向けか | ネタごとに1つに絞って言い切る（これから売り始める人／くり返し仕入れる店・リセラー／コレクター など）。[商品を決める](references/research.md)の3。 |
| 型（見せ方） | [型カード](references/types.md)の主力の型から選ぶ。表の「参考帳」タブの手本は、構成と文字の内容を借りるために使う。 |
| 色・書体 | 商品そのものの色に合わせる。[型カード](references/types.md)に従う。 |
| 毎回変えないもの | 合言葉（`contact.keyword`）、締めのアカウント名（`closing`）、上の固定の文字の出し方、締めの出し方。 |

## 毎日の流れ（ネタを出し、案を作る）

毎日、ネタを `plan_count` の数（既定は5つ）出す。`plan_approval` が `chat` なら、人が選んだネタだけを作る（1つでも、全部でもよい。選ばれなければ作らない）。`all` なら、ネタをチャットに出してから、選ばれるのを待たずに全部作る（人が止めた案は作らない。直しの指示があった案は、直してから作る）。`off` なら、`daily_set` の数（既定は **リール1本・カルーセル1本・画像1本**）だけ自分で選んで作る。案は商品を別にする。できた案のうち、人は気に入った案にだけ「投稿OK」のチェックを入れる。

各工程で読む説明書は右の列だけ。先に全部を読まない。

| 順 | やること | その時に読む説明書 |
|---|---|---|
| 1 | `client.json` と、表の「投稿」タブの直近14日分、「聞かれた商品」タブの直近14日分を読む。投稿済みの行の数字を、取れるものは全部取って、その行に書く（国・年代まで） | [表の書き方](references/sheet.md)／[投稿する](references/publish.md) |
| 2 | その日の動きを調べて「同業者の動き」と「商品の候補」に足し、ネタ（商品・誰向け・形式・型・なぜ今か）を出す。`plan_approval` が `chat` なら、チャットに出して、人が選ぶのを待つ（**選ばれるまで、3から先へ進まない**）。`all` なら、チャットに出してから待たずに進む | [商品を決める](references/research.md) |
| 3 | 参考帳に新しい手本を1〜2件足す。選んだ参考投稿の全ページ・全編と、商品の画像を保存する | [素材を取ってくる](references/assets.md) |
| 4 | 参考を測って、案を作る | [参考の測り方](references/reproduction.md)／[作り方](references/production.md)／[型カード](references/types.md) |
| 5 | 画面の文字と本文を、英語と日本語訳で書く（本文はInstagramとFacebookで同じ1つ） | [文章](references/copy.md) |
| 6 | 完成物を開いて検品し、不合格は直す | [検品](references/check.md) |
| 7 | 完成物と「見た目」の画像を共有フォルダに上げる。「投稿」タブに1案1行、「素材」タブに使った素材を書き、読み戻して確かめる。カルーセルはページを1枚ずつ上げ、「1枚目」〜「10枚目」の欄にリンクを1つずつ入れる | [表の書き方](references/sheet.md) |

### ネタの組み合わせの決まり

商品の選び方と、ネタどうしの組み合わせは[商品を決める](references/research.md)の3。型については次のとおり。

- **どの案も、価格か頼み方と、行動の案内（合言葉のDM）を同じ投稿に入れる。** 商品の魅力や値動きだけを見せて終わる案を作らない。
- ネタは[型カード](references/types.md)の主力の型（A〜E）から選ぶ。補助の型は、出すネタのうち1つまで。出すネタのうち2つ以上は、A（日付入り価格）かB（価格表）にする。
- **同じ型を続けて使ってよい。** 効く型は繰り返す。変えるのは商品と数字。
- 新弾・予約の商品と、同業者が今出している商品は、日付と価格が変われば毎日出してよい。それ以外の商品は、3日以内に繰り返さない。同じ商品・同じ数字・同じ型の案を、14日以内に2回出さない。
- 型E（梱包と実績）は、`footage_folder` に実写か、お客さんのレビューの画面があるときだけ作る。あるときは、ネタの1つを型Eにする。
- **どのネタも、誰に向けた投稿かを1つに絞って言い切る。** 出すネタの中で、誰向けを2種類以上にする。
- 「聞かれた商品」タブに書かれた商品を先に選ぶ。その商品を出したときの型も、多く選ぶ。「買う言葉のコメント」は記録として残すが、同業者でも付く数が少ないので、型や商品を選ぶ根拠にしない。
- 過去の行で「ストック」になっている案は、人が選ばなかった案。7日以内なら、価格を取り直して今日のネタの1つとして出し直してよい（1日1つまで）。

### うまく作れない案があるとき

その案だけ、別の商品か別の参考に替えて作り直す。3回替えても作れなければ、その日は作れた案だけを表に書き、作れなかった案は「状態」を `見送り` にして理由を書く。弱い案で数を埋めない。

## 制作フォルダ

`client.json` の `output_folder` の下に、1案につき1つ作る。スキルのフォルダの中には保存しない。

```text
<output_folder>/YYYYMMDD-A_商品の短い名前/     （A・B・C… は案の記号。ネタの番号1がA、2がB。表の投稿IDと同じ）
  01_調査.md        なぜ今か、今日の価格、出典、確かめた日時、選んだ理由
  02_分解.md        参考の全ページ・全編の実測
  03_文章.md        画面の文字と本文（英語と日本語訳）
  reference/        参考投稿の原本（全枚・全編）と media-manifest.json
  assets/           商品の原画像、生成した背景
  index.html ほか   編集元
  reel_v1.mp4 / slides_v1/ / image_v1.png   完成物（直したら v2、v3 と上げる。上書きしない）
  preview_v1.jpg    表に貼る「見た目」の画像
  checks/           検品で開いたコマ、参考と並べた比較
```

## 道具

スキルのフォルダを作業場所にして実行する。初回だけ [START_HERE.md](START_HERE.md) の準備をする。引数と実行例は[作り方](references/production.md)にある。

| したいこと | 実行するもの |
|---|---|
| 環境がそろっているか確かめる | `node scripts/check_env.mjs` |
| `client.json` の足りない欄を出す | `node scripts/check_client.mjs` |
| ブラウザーが無いPCに試験用のChromeを入れる | `npm run browser` |
| 参考投稿の原本を順番どおり取り込む | `python scripts/import_reference.py` |
| 参考動画のカット候補を出す | `python scripts/analyze_reference_video.py` |
| カルーセル・画像を書き出す | `node scripts/shoot_slides.mjs` |
| リールのコマを撮る | `node scripts/capture_frames.mjs` |
| 効果音を時刻どおりに並べる | `python scripts/mix_audio.py` |
| コマと音をMP4にして中身を確かめる | `node scripts/finish_video.mjs` |
| 表に貼る「見た目」の画像を作る | `python scripts/make_preview.py` |
| 参考と完成物を並べて比べる | `python scripts/compare_reference.py` |
| 生成画像の付加情報を消す | `python scripts/clean_metadata.py` |

## しないこと

- `plan_approval` が `chat` のときに、ネタが選ばれる前に画像や動画を作ること。
- 「投稿OK」にチェックの無い行の投稿、DM・コメントの送信。
- 「投稿OK」の欄を書き換えること。
- 利益の額や率を約束する言葉、関税や税金の率・額の言い切りを、画面や本文に書くこと。お客さんのレビューを書いて作ること。
- 確かめていない在庫数・発送日・最安・実績を、画面や本文に言い切りで書くこと。価格を出す案でも、`in stock` など手元にあると読める言葉は使わない。
- 画面の揺れ・フラッシュ・細かいカットを重ねて、動きの多さで見せようとすること。
- 商品の絵柄・番号・文字をAIで描き直すこと。人物や在庫の山をAIで作ること（背景と飾りは生成してよい）。
- 商品画像に、鑑定品のラベルやケースなど、元の画像に無いものを描き足すこと。
