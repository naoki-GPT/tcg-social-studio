# 素材を取ってくる

参考投稿と商品の画像は、**このスキルが自分で開いて保存する。** 人に「素材をください」と頼んで止まらない。

## 1. 参考を選ぶ

表の「参考帳」タブから、今日作る案それぞれに1つ選ぶ。状態が `使う` か `候補` の行だけ。主力の型は、見た目と動きを[型カード](types.md)で決めるので、手本からは「何を・どの順で見せ、どんな文字を出しているか」を借りる。

- その案の形式に合わせる（リールの案にはリールか作り替えられる参考、カルーセルの案にはカルーセル）。
- 商品と合う型を選ぶ。価格表を見せたい商品に、1枚の魅力を語る型を当てない。
- 同じ型の手本を続けて使ってよい。同じ手本（同じ参考ID）は、7日あける。
- **原本が保存済みの行を先に選ぶ。**（下の「2. 参考投稿の原本をそろえる」の保存済みの一覧にある参考ID）
- 選んだら、その行の「最後に使った日」に今日の日付を書く。

### 「必要な素材」ごとの使い方

| 必要な素材 | どう使うか |
|---|---|
| カード画像と文字だけで作れる | 全ページ・全編を測って、そのまま再現する（[参考の測り方](reproduction.md)）。 |
| 実物の映像が要る | **構成とテンポだけを借りる。** 何を・どの順で・何秒ずつ見せているか、文字がいつ出るかを測り、実物の映像の代わりにカード画像を置く。見た目は[型カード](types.md)で決める。表の「気になる点」に「実写の参考をカード画像で作り替え」と書く。 |
| 人物が主役 | 作る手本にしない。言っている内容（何を得だと言っているか）だけ読む。 |

**リールは、実写の参考をカード画像で作り替えるのが基本。** その構成（何をどの順で見せるか）と、文字の内容・出る時刻を借りる。カットの速さや効果の多さは借りない。

### 実写の置き場を先に見る

`client.json` の `footage_folder` が空でなければ、毎日の制作の最初にそのフォルダを開く。その相手が撮った映像・写真（商品を手に持った様子、梱包の手元、発送する箱など）があれば、カード画像より先にそれを使う。**お客さんのレビューの画面**（届いたあとのDMや感想を保存した画像）も、ここに入れてもらう。撮影をしない相手でも、レビューの画面だけなら用意できる。

- 使った実写は、表の「素材」タブに `種類＝その他`、`元のアドレス＝本人の撮影` で書く。
- 映っている商品と、案の商品が同じであることを確かめる。別の商品の映像を、その商品として使わない。
- 顔、住所、送り状の宛名、他人の名前が映っていたら、その部分を隠すか、その素材を使わない。
- レビューの画面は、お客さんの名前・アカウント名・顔写真・住所を隠してから使う。書かれた文は変えない。同じレビューを、14日以内に2回使わない。レビューを自分で書いて作らない。
- `footage_folder` が空、または中身が無いときは、実写なしで作る。型E（梱包と実績）は作らない。
- 実写かレビューの画面があるときは、その日のネタの1つを型Eにする（[商品を決める](research.md)の3）。

## 2. 参考投稿の原本をそろえる

### 先に、保存済みの原本を使う

参考帳の手本のうち37件は、原本（全ページ・全編）が保存済み。GitHubのリポジトリの `reference-originals/` にある（スキルのフォルダから見て `../../reference-originals/`）。

```text
reference-originals/
  index.json          保存済みの参考IDと、投稿のアドレス・形式・ファイル名の一覧
  R001/ p01.jpg p02.jpg ...     カルーセルと画像（cover.jpg は表紙）
  R036/ video.mp4 f1.jpg ...    リール（全編と、抜き出したコマ）
```

選んだ参考IDのフォルダがあれば、その中身を制作フォルダの `reference/` に写して、そのまま測る。投稿を開いて保存し直さなくてよい。`02_分解.md` の最初に「保存済みの原本を使用」と書く。

`reference-originals/` が無いPC、または選んだ参考IDのフォルダが無いときだけ、下の手順で自分で保存する。

### 自分で保存する

自分のブラウザーで投稿を開き、**全ページ・全編**を保存する。

- カルーセルは全枚を元の順番で。先頭の1枚、サムネイル、縮小画像だけで済ませない。投稿に表示されている枚数を数え、保存した枚数と合わせる。
- 動画は全編を、元の解像度と音つきで保存する。
- 投稿の本文（キャプション）も全文を控える。
- 開いた日時と投稿のアドレスを控える。

保存したら、原本を制作フォルダへ順番どおり取り込む。枚数が合わない、同じファイルが混ざっている、空のファイルがある、のどれかで止まる。

```powershell
python scripts/import_reference.py --post-url <投稿のアドレス> --expected <元の枚数> --out <制作フォルダ>/reference <1枚目> <2枚目> ...
```

**原本を見ずに、メモだけで作り始めない。** 保存済みの原本も無く、自分で保存もしていない参考で作らない。自分で保存するときは、何を試してどうなったかを `02_分解.md` の最初に書く。

### 開けない・保存できないとき

順に試す。人に聞かない。

1. 同じ投稿を別の開き方で試す（埋め込み表示など）。
2. PCに動画保存の道具（yt-dlp など）が入っていれば使う。新しく有料のサービスを契約しない。
3. それでも全枚・全編がそろわなければ、**保存済みの原本がある別の行に替える。** 参考帳の取れなかった行の「メモ」に、取れなかった日を書き足す。新しく有料の取得サービスは使わない。
4. 保存済みの原本も無いPCでは、参考帳の「見た目」の画像・「メモ」・[型カード](types.md)から作る。このとき、表の「気になる点」に必ず「参考の原本を保存できず、参考帳のメモと型から制作」と書く。実物を測っていないことを隠さない。

削除された投稿、ログインしないと見られない投稿は使わない。ログイン情報を入力して突破しない。

## 3. 商品の画像を取ってくる

- 今日の商品そのものの画像を、次の順に探して保存する：①メーカーの公式の商品ページ　②スニーカーダンクの商品ページ　③PriceCharting などの相場サイトの商品ページ。
- **他人の出品写真は使わない。** メルカリ・ヤフオク・eBay などで個人や店が出品のために撮った写真は、切り抜いても使わない。画像検索で出てきた画像も、元が出品写真なら使わない。
- 上の①〜③で画像が見つからない商品は、**その商品をやめて、別の商品に替える。**
- 保存した画像を開き、**商品名・番号・言語・版・状態**が今日の商品と一致することを確かめる。似た別の番号を使わない。
- 小さなサムネイルしか無ければ、別の正規の大きい画像を探す。
- 透かしを消さない。別の番号に差し替えない。カードの文字や絵をAIで描き直さない。
- 英語版と日本語版を並べるときは、それぞれの原画像を使う。
- 画像のまわりの余白は、置くときの位置・大きさ・切り抜きで整える。カード本体・番号・著作権表示は切り落とさない。
- 1枚ずつ紹介する型や、たくさん並べる型では、必要な枚数の画像をそろえる（1枚ずつ紹介なら6〜8枚、並べる型なら12枚以上が目安）。そろわなければ商品か型を替える。

## 4. 足りない場面を作る

背景・飾り・空のカードファイルなどは画像生成（既定は gpt-image-2）で作ってよい。商品・価格・文字は、確かめた原画像と文字組みを上に重ねる。

背景の指示の例（数字や色はその回に合わせる）：

> 4:5のトレーディングカード価格比較用背景。左右2列で、中央に十分な間隔。左は落ち着いた赤、右は紺。上部に見出し、中央に実商品を大きく置く余白、下部に価格と条件を書く余白。商品・カードの絵・ロゴ・数字・文字・国旗を描かない。後から正確な商品画像とテキストを重ねる。

- 生成に商品画像を参考として渡した場合は、できた画像を開き、商品が描き直されていないか元と見比べる。崩れていたら、原画像＋HTMLの重ね置きに戻す。
- 生成した画像は付加情報を消してから使う。原本は残す。

```powershell
python scripts/clean_metadata.py <生成した画像> --out <制作フォルダ>/assets/background.jpg --report <制作フォルダ>/checks/metadata.json
```

- 人物、倉庫、在庫の山、発送の場面は生成しない。
- 画像生成が使えない日は、取得した商品画像とHTMLだけで作れる形にする。

## 5. 表に残す

使った素材を、表の「素材」タブに1素材1行で書く（[表の書き方](sheet.md)）。「見た目」にその素材の画像を出す。どこから・いつ取ったかは、制作フォルダの `01_調査.md` にも残す。投稿の画面や本文には、出典の注意書きを足さない。

## 6. 参考帳に新しい手本を足す

「参考帳」タブは、作るときの手本の一覧。**毎日、制作の最初に、新しい手本を1〜2件足す。** 人に頼まれるのを待たない。見るアカウントは日ごとに2〜3個ずつ順番に回す。

### 探し方

入口はアカウント。`client.json` の `reference_accounts` と、「参考帳」に載っているアカウントの、前回見たとき以降の投稿を見る。いいね数だけで広く探さない（フォロワーの多い収集家や開封動画ばかりが上に来て、販売の手本にならない）。

### 足す条件

1. **買う言葉のコメントが付いている、または、そのアカウントの中で伸びている。** コメントに `Price?` `How much?` `Still available?` `DM sent` `How do I buy?` などの買う言葉があれば、いいねが少なくても足す（販売の投稿は、いいねが少なくても売買が動いている）。無ければ、同じアカウント・同じ形式（画像／カルーセル／リール）の最近の投稿と比べて、いいね＋コメントがおよそ2倍以上。別のアカウントの数字とは比べない。「メモ」に、買う言葉のコメントの件数と原文を1〜2つ書く。
2. **全ページ・全編を開いて見た。** 先頭の1枚だけで決めない。
3. **プレゼント企画ではない。** 「コメントで応募」の投稿は、景品で反応を集めているので手本にしない。

### 分類して書く

1件ずつ、次を決めて「参考帳」タブに書く。

| 欄 | 決め方 |
|---|---|
| 状態 | 新しく足すものは `候補`。1度使って問題なければ `使う` に変える。 |
| 型 | 何を見せる投稿か（価格表、値動き、ラインナップ、予約の告知、1枚ずつ紹介 など）。既にある型の名前に合わせる。無ければ新しい名前を付ける。 |
| 必要な素材 | `カード画像と文字だけで作れる`／`実物の映像が要る`／`人物が主役` |
| 使い方 | すぐ下の表のとおり |
| 見た目 | 先頭3ページ、または動画の3コマを横に並べた画像（`make_preview.py`） |

| 必要な素材 | 使い方 |
|---|---|
| カード画像と文字だけで作れる | そのまま再現する |
| 実物の映像が要る | 構成とテンポを借りて、カード画像版に作り替える |
| 人物が主役 | 言っている内容（訴求）の参考だけ。作る手本にしない。状態は `訴求の参考` |

新しいアカウントを見つけたら、「参考帳」に書くだけでよい。次からそのアカウントも順番に入れる。

条件に合う投稿が見つからない日は、足さずに進む。全ページ・全編を開いて保存できなかった投稿も足さない。手本を足せない日が続いても、制作は保存済みの原本で進める。
