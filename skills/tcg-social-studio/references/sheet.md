# 表の書き方

使うスプレッドシートは `client.json` の `sheet_url` の1つだけ。タブは5つ。**人が見るのは「投稿」タブだけ**で、ほかの4つはこのスキルが使う。

| タブ | 1行は何か | 書く時 |
|---|---|---|
| 投稿 | 1つの案（1投稿） | 毎日、3行 |
| 素材 | 1つの素材（参考投稿・商品画像・背景） | 毎日、使った分 |
| 参考帳 | 1つの参考投稿（手本） | 毎日1〜2件足す。使ったら「最後に使った日」を書く |
| 商品の候補 | 1つの商品 | 毎日足す。使ったら「使った日」を書く |
| 数値の記録 | 1つの数字（1投稿・1指標・1回の取得） | 投稿した後 |

## 書くときの決まり

0. **ひな形には書かない。** `sheet_url` のアドレスに、ひな形のID `19XXnnN8qqeR9QfVx0vm2pTFGMYACJrmC0l2njbYKO2M` が入っていたら、それはコピー元。何も書かずに止まり、「`sheet_url` がひな形のままです。コピーした表のアドレスに直してください」と伝える（`node scripts/check_client.mjs` が確かめる）。見分けるのはアドレスで、表の名前ではない。コピーした表の名前に「ひな形」の文字が残っていても、そのまま書いてよい。
1. **列は位置ではなく、1行目の見出しの名前で探して書く。** 列の並びが変わっていても、見出しの名前が同じ列に入れる。見出しが見つからなければ、書かずに止まって、無い見出しを伝える。
2. **新しい行は一番下に足す。** 過去の行を消さない、並べ替えない。
3. **選択式の欄は、決まった言葉だけを入れる。**（下の各表の「選べる言葉」）
4. **書いたら読み戻す。** 書いた行をもう一度読み、欄がずれていないか、本文が途中で切れていないか、画像が出ているかを確かめる。

## 「見た目」の欄（画像を出す）

「投稿」「素材」「参考帳」「商品の候補」の各タブには「見た目」の欄がある。人がアドレスを開かなくても、どんな画像・動画かが一目で分かるようにするための欄。

1. 表示する画像を用意する。完成物と参考投稿は `make_preview.py` で作る（リールは3コマ、カルーセルは先頭3枚、画像はその1枚）。商品画像と背景は、その画像そのもの。
2. その画像を、`share_folder_url` の共有フォルダに置き、「リンクを知っている全員が閲覧できる」設定にする。**ここまでが毎日の制作の一部。** PCの中に置いたままで終わらせない。完成物（動画・スライド・画像）も同じフォルダに上げ、「完成物」の欄にはそのアドレスを書く。コマ撮りの連番画像と書体は上げなくてよい。
3. 欄に `=IMAGE("画像のアドレス")` の式を入れる。Googleドライブに置いた画像は `=IMAGE("https://drive.google.com/thumbnail?id=<ファイルのID>&sz=w800")` の形にする。
4. 書いた後、欄に画像が出ているかを確かめる。出ていなければ共有の設定を直す。

画像が出せないときは、欄を空のままにせず、どんな画像かを10字ほどで書く（例：`紺の価格表4枚`）。

### 状態の流れ

- 作った日：3行とも `投稿待ち`。
- 投稿した行：`投稿済み`（[投稿する](publish.md)で書き換える）。
- 次の日の制作を始めるとき、前の日までの `投稿待ち` でチェックの無い行は `ストック` に変える。作ってから7日を過ぎた `ストック` はそのまま残す（消さない）。
- 作れなかった案：`見送り`。「商品」に試した商品、「選んだ理由」に作れなかった理由を書き、完成物と文章は空にする。

### 「気になる点」に書くこと

人が判断するときに知らないと困ることだけ。

- 近い書体で代用した、参考の音を聞いて確かめられなかった、など参考と違う点。
- 実写の参考をカード画像で作り替えたこと。
- OtoLogic の音を使ったので本文にクレジットが入っていること。
- 価格を確かめた日時。
- 取得できなかった素材と、代わりに使ったもの。

## 「素材」タブ

その日の案に使った素材を、1素材1行で書く。

| 見出し | 書くもの | 選べる言葉 |
|---|---|---|
| 見た目 | その素材の画像 | — |
| 投稿ID | どの案で使ったか | — |
| 種類 | | `参考投稿`／`商品画像`／`背景`／`その他` |
| 内容 | 何の画像か（商品名・番号、または「背景：紺と金」など） | — |
| 元のアドレス | 取ってきたページ、または「生成」 | — |
| 保存先 | 共有フォルダの中のアドレス | — |
| 取得日 | YYYY-MM-DD | — |

## 「参考帳」タブ

| 見出し | 書くもの | 選べる言葉 |
|---|---|---|
| 見た目 | 先頭3ページ、または動画3コマ | — |
| 参考ID | `R001` からの連番。新しい行は最後の番号の次 | — |
| 状態 | | `使う`／`訴求の参考`／`候補`／`使わない` |
| アカウント／形式／枚数・秒数／型／商品の種類 | 投稿を開いて見たとおり | 形式と商品の種類は「投稿」タブと同じ |
| 必要な素材 | | `カード画像と文字だけで作れる`／`実物の映像が要る`／`人物が主役` |
| 使い方 | [素材を取ってくる](assets.md)の表のとおり | — |
| 伸び（倍）／いいね／コメント／投稿日／アドレス | 見たときの数字 | — |
| メモ | 構成の要点（何枚目に何があるか、何秒ごとに切り替わるか） | — |
| 最後に使った日 | この参考で作った日 | — |

作るときに選ぶのは、状態が `使う` か `候補` の行。`訴求の参考` は、言う内容を考えるときだけ読む。`使わない` は選ばない。人が状態を書き換えていたら、それに従う。

## 「商品の候補」タブ

| 見出し | 書くもの |
|---|---|
| 見た目 | 商品の画像 |
| 商品の種類 | 「投稿」タブと同じ選べる言葉 |
| 商品 | 商品名・番号・言語・状態・単位 |
| 海外で売れた記録 | サイト名、直近30日の件数、最後に売れた日 |
| 海外の価格／国内の価格／差 | 調べた日の数字。通貨を付ける |
| 調べた日 | YYYY-MM-DD |
| 出典 | 開いたページのアドレス。その後に見送った日があれば理由も |
| 使った日 | 案に使った日。2回使ったら2つ書く |

## 「数値の記録」タブ

投稿後に取った数字を、1つの数字につき1行で足す（投稿ID、取得日時、指標、値、取得元）。取れなかった指標は行を作らない。0 で埋めない。「投稿」タブの右端の欄には、いちばん新しい数字だけを書く。
