# 表の書き方

使うスプレッドシートは `client.json` の `sheet_url` の1つだけ。タブは7つ。**人が見るのは「投稿」タブ、人が書くのは「聞かれた商品」タブ**で、ほかの5つはこのスキルが使う。

| タブ | 1行は何か | 書く時 |
|---|---|---|
| 投稿 | 1つの案（1投稿） | 毎日、作った案の数だけ |
| 素材 | 1つの素材（参考投稿・商品画像・背景） | 毎日、使った分 |
| 参考帳 | 1つの参考投稿（手本） | 毎日1〜2件足す。使ったら「最後に使った日」を書く |
| 商品の候補 | 1つの商品 | 毎日足す。使ったら「使った日」を書く |
| 同業者の動き | 同業者の1つの投稿 | 毎日、直近7日の投稿でまだ書いていないもの |
| 聞かれた商品 | 聞かれた1つの商品 | 人が書く。スキルは読むだけ |
| 数値の記録 | 1つの数字（1投稿・1指標・1回の取得） | 投稿した後 |

## 書くときの決まり

0. **ひな形には書かない。** `sheet_url` のアドレスに、ひな形のID `19XXnnN8qqeR9QfVx0vm2pTFGMYACJrmC0l2njbYKO2M` が入っていたら、それはコピー元。何も書かずに止まり、「`sheet_url` がひな形のままです。コピーした表のアドレスに直してください」と伝える（`node scripts/check_client.mjs` が確かめる）。見分けるのはアドレスで、表の名前ではない。コピーした表の名前に「ひな形」の文字が残っていても、そのまま書いてよい。
1. **列は位置ではなく、1行目の見出しの名前で探して書く。** 列の並びが変わっていても、見出しの名前が同じ列に入れる。見出しが見つからなければ、書かずに止まって、無い見出しを伝える。ただし、下の「前の版の表に足す列」に挙げた見出しが無いときは、止まらずに、そのタブの右端に列を足し、1行目に見出しを書いてから使う（挙げた順に足す。ほかの列は動かさない）。
2. **新しい行は一番下に足す。** 過去の行を消さない、並べ替えない。足すときは、先にそのタブを読んで最後の行の番号を数え、「タブの名前と行番号」で範囲を指定して書く。書く場所を道具まかせにする足し方（自動で末尾に追加する機能）は使わない。別のタブや別の列に書かれることがある。
3. **選択式の欄は、決まった言葉だけを入れる。**（下の各表の「選べる言葉」）
4. **書いたら読み戻す。** 書いた行をもう一度読み、欄がずれていないか、本文が途中で切れていないか、画像が出ているかを確かめる。

## 「見た目」の欄（画像を出す）

「投稿」「素材」「参考帳」「商品の候補」の各タブには「見た目」の欄がある。人がアドレスを開かなくても、どんな画像・動画かが一目で分かるようにするための欄。

1. 表示する画像を用意する。完成物と参考投稿は `make_preview.py` で作る（リールは3コマ、カルーセルは先頭3枚、画像はその1枚）。商品画像と背景は、その画像そのもの。
2. その画像を、`share_folder_url` の共有フォルダに置く。共有フォルダが「リンクを知っている全員が閲覧できる」設定なので、中に入れたファイルも同じ扱いになる。**ファイル1つずつに共有の設定をしない**（そのたびに人に許可を求める画面が出て、制作が止まる）。**ここまでが毎日の制作の一部。** PCの中に置いたままで終わらせない。完成物（動画・スライド・画像）も同じフォルダに上げ、「完成物」の欄にはそのアドレスを書く。コマ撮りの連番画像と書体は上げなくてよい。直した完成物は、制作フォルダと同じく名前に版を付けて上げる（`reel_v2.mp4`、`slides_v2/`、`preview_v2.jpg`）。同じ名前のファイルを同じフォルダに2つ置かない。
3. 欄に `=IMAGE("画像のアドレス")` の式を入れる。Googleドライブに置いた画像は `=IMAGE("https://drive.google.com/thumbnail?id=<ファイルのID>&sz=w800")` の形にする。
4. 書いた後、欄に画像が出ているかを確かめる。出ていなければ、共有フォルダの設定を確かめて直す。

**「見た目」の欄には、必ず画像の式を入れる。** この4つのタブのどの行も同じ。言葉（「BOXの画像」など）を書いて済ませない。空のままにもしない。画像が出ないときは、原因（共有の設定、アドレスの間違いや途中切れ）を直してから次へ進む。

### カルーセルのページの欄

人が1ページずつ開いて見られるようにする欄。

1. ページの画像は、1枚ずつ別のファイルとして共有フォルダに上げる（`slides_v1/01.png`、`02.png`…）。
2. 「1枚目」の欄には1ページ目、「2枚目」の欄には2ページ目…と、ページの順に入れる。式は `=HYPERLINK("https://drive.google.com/file/d/<ファイルのID>/view","1枚目")` の形（表示する言葉は欄の見出しと同じ）。
3. ページより多い欄は空のまま。カルーセルは10枚までにする（11枚以上の案は作らない）。
4. 書いたら、1つずつ押して、そのページの画像が開くことを確かめる。

### 前の版の表に足す列

前の版で作った表には、次の列が無いことがある。無ければ、決まり1のとおり、右端に足してから使う。人に頼まなくてよい。

- 「投稿」タブ：`相場と出典`（4.4.5）、`リーチ`、`シェア`、`プロフィールへのアクセス`、`フォロー`、`国（多い順）`、`年代（多い順）`、`数字を取った日時`、`取れなかった数字`、`1枚目`〜`10枚目`（4.5.0）
- 「数値の記録」タブ：`媒体`（4.5.0）
- 「投稿」タブ：`買う言葉のコメント`（5.0.0）
- 「商品の候補」タブ：`発売日`、`なぜ今か`（5.1.0）

「同業者の動き」タブと「聞かれた商品」タブ（5.1.0）が無い表では、止まらずにタブを作り、1行目に下の見出しを書いてから使う。

**タブや列を足すときは、今ある表と同じ見た目にする。** 新しいタブは、白紙から作らない。今ある「商品の候補」タブを複製し、2行目から下の中身を消し、タブの名前と1行目の見出しを書き換えて作る（余った列は消す）。こうすると、見出しの色・文字の太さ・固定した1行目・列の幅・折り返し・文字の大きさが、今の表と同じになる。複製ができない道具のときは、「商品の候補」タブの1行目と2行目の書式を写す。新しい列は、左隣の列の書式（見出しのセルと、その下のセル）を写して足す。「選べる言葉」が決まっている列には、今ある列と同じ形の選択式（プルダウン）を付ける。日付の列は、ほかのタブの日付の列と同じ表示にする。すでに違う見た目で作ってしまったタブや列があれば、中身は消さずに、書式だけを上のとおりに直す。足したあと、今あるタブと並べて見て、同じ見た目になっているかを確かめる。

### 状態の流れ

- 作った日：作った行はどれも `投稿待ち`。
- 投稿した行：`投稿済み`（[投稿する](publish.md)で書き換える）。
- 次の日の制作を始めるとき、前の日までの `投稿待ち` でチェックの無い行は `ストック` に変える。作ってから7日を過ぎた `ストック` はそのまま残す（消さない）。
- 作れなかった案：`見送り`。「商品」に試した商品、「選んだ理由」に作れなかった理由を書き、完成物と文章は空にする。

### 「気になる点」に書くこと

人が判断するときに知らないと困ることだけ。

- 近い書体で代用した、参考の音を聞いて確かめられなかった、など参考と違う点。
- 実写の参考をカード画像で作り替えたこと。
- ストックから出し直した案で、価格を読み直して作り直したこと。
- OtoLogic の音を使ったので本文にクレジットが入っていること。
- 取得できなかった素材と、代わりに使ったもの。

## 「数値の記録」タブ

投稿後に取った数字を、1つの数字につき1行で足す（投稿ID、取得日時、指標、値、取得元、媒体）。媒体は `Instagram`／`Facebook`。取れなかった指標は行を作らない。0 で埋めない。「投稿」タブの数字の欄には、いちばん新しい数字だけを書く（[投稿する](publish.md)の「数字を取る」）。国と年代は、1つの国・1つの年代につき1行（指標＝`国:US`、値＝`42%` のように）。
