# Museと制作プログラムの素材受け渡し

版2.2／2026-11-13。調査・素材の用意はMuse側で、その環境にある公開情報調査機能と許可済みの手元ファイルを使う。制作プログラムは受け取ったローカル素材を読み込む。追加の外部収集サービスへの契約・認証を制作開始条件にしない。

取得手段があっても、参考の全枚／全編を得られたかは別に確認する。本文・表紙・サムネイルだけで完成素材としない。指定参考が取得できなければ不足を明示し、別参考へ勝手に変更しない。利用者から受け取る必要がある場合は、足りない素材だけを一度に伝える。ブラウザーUI操作禁止は守る。

## ローカル素材の一覧

[入力例](../templates/media-input.example.json)を案件フォルダへコピーする。元投稿URL、参考ID、形式、元の期待枚数、順序、各ファイルの場所を記入。画像1枚と動画全編はexpected_countを1、カルーセルは実際の全枚数にする。原本の枚数が不明なら確定した値を作らない。

ファイルの相対パスは入力JSONの場所から解決する。出力は未使用の新しいフォルダにする。

```powershell
python scripts/import_reference_media.py ../制作物/media-input.json --out ../制作物/reference-v1
```

全ファイルの存在、順序、枚数、画像のデコードを確認し、順序付きのコピーと `media-manifest.json` を作る。原本は変更しない。同じファイルを複数ページとして繰り返す入力、不足、既存出力への上書きは停止する。

`complete: true` は一覧の全ファイルを保存できた意味。元投稿との一致、動画の正常再生、文字・効果の全編確認、利用条件は別に検品する。受け取り後は全画像を開き、動画を全編再生し、[分解手順](reference-reproduction.md)へ進む。

調査の数値は元URL、観測時刻、対象期間、指標の意味とともに別記録へ。取得できない数値を0へ置換せず、1回の観測だけで伸び率を作らない。秘密情報、管理画面、他案件の資料を受け渡しに混ぜない。
