# 素材から完成画像・動画へ

版2.0追記：需要・導線・全参考の再現はSKILL.mdと[全参考仕様](reference-reproduction.md)を優先する。以下の旧テンプレートの秒数や先頭画像の観察範囲は、今回の完成仕様ではない。2026-11-12の再確認は[実物の索引](verified-reference-map.md)を参照。
## 設計

`BRIEF.md` に、対象客、目的、参考URLと確認範囲、引き継ぐ訴求、商品、秒割り、素材ID、画面の文、投稿本文の案内先を残す。元動画の時刻と自作の時刻は別列。未確認の動画を見た前提で再現しない。

顔出しなしで、一覧→選択→同じ単品、絵柄の寄り、条件比較、注文手順などを使う。必要な素材を決めてから探す。既存Facebook投稿の写真・色・文体を、Instagramへ一律適用しない。

## 商品画像

取得後、画像を開いて商品名・番号・言語・絵柄・状態を照合。小さなサムネイルしかない場合は別の正規の高解像度候補を探す。透かし除去、別番号への置換、AIによる文字再描画はしない。

画像の透明な余白はHTMLの位置・サイズ・クリップで調整可能。`crop:[x,y,w,h]` は原画像全体を1とした表示範囲。カード本体、番号、著作権表示を落とさず、原画像の外側の余白を対象とする。既定 `[0,0,1,1]`。カードごとに実画面を見て決め、スニダン画像すべてを同じ座標と決めつけない。

## AI補完

商品をそのままHTML配置し、背景・空きファイルなど必要な具体的場面を生成する方法を優先。画像編集機能で背景を変える場合も、元商品を開いてから参照し、編集後に文字・絵柄・枚数・封・傷を照合する。失敗時は原画像＋HTMLへ戻す。

生成指示例：

> 縦9:16、カードファイルを真上から見た説明用の写真。透明ポケットが3列3行、すべて空。カード本体・文字・ロゴ・人・手は描かない。後で正確な商品画像をHTMLで重ねる。上下に字幕用の余白。本人の在庫・購入実績の証拠として使わない。

生成機能、指示全文、参照元、原本、採用版、確認できたモデルIDを保存。生成不可なら別の勝手な従量APIを起動しない。意味の薄い背景や撮影待ちリストだけへ置き換えず、取得素材だけの完成形も検討する。

生成画像の付加情報除去：

```powershell
python scripts/clean_metadata.py "../制作物/assets/generated.png" --out "../制作物/assets/background.jpg" --report "../制作物/checks/metadata.json"
```

原本保持。画素の再保存と向き補正がある。AI加工の来歴は別の素材表へ残し、架空のカメラ情報や撮影日を追加しない。

## HTML動画

同梱テンプレは編集用の出発点。参考に合わなければ構成を変える。`content.js` でカード一覧、選ぶカード、各場面の文、画像の配置を設定する。カードが少ないときは枠を埋めるために架空カードを増やさず、列数や見せ方を調整する。

空きファイルは、生成背景へカードを置くなら `binder.slots` の座標を実画像から設定。背景がなければHTMLで分かる空きポケットの説明画として作れる。生成済みと偽らない。

時間は `segments` の単調増加する8個の時刻で決める。初期値 `[0,3,5,7,10,14,18,24]` は開始・終了を含む7場面・24秒の例。短縮するときは字幕を読む時間を確認。固定15秒や、毎秒の動き量を満たすための過度な動きを強制しない。

`window.__seek(t)` は同じ時刻へ戻ると同じ画面にする。画像をローカルへ保存し、外部フォント・外部JSへ依存しない。実際の動画や音声を含む場合は、フレーム撮影だけでは同期できないので、利用可能な動画編集環境で映像・音声を適切に処理する。同梱レンダラーは画像＋HTMLの無音動画用。

## 検品

1. `inspect.mjs`：画像欠損、ブラウザのエラー、同時刻の再表示、場面境界を確認し静止画を保存。
2. `render.mjs`：MP4を新しい名前で出力。
3. `verify_video.mjs`：実際のMP4の尺・縦寸法・fps・音声有無・黒コマと場面抽出。
4. `contact_sheet.py`：元の縦比率を維持した一覧と表紙を作る。横長用のサイズへ押し潰さない。
5. 画像を開いて商品同一性、選択枠、文字の重なり、相談先、画面端と投稿UIの余白を確認。表紙の文が単独で分かるかも見る。

機械的な動き量は診断材料。読ませる保持区間をエラー扱いして無意味に揺らさない。ループする設計だけ開始と終わりを合わせる。無音版は無音と伝える。

確認記録に、合格・修正・未確認、どの版を実見したかを記入。HTMLが正しくてもMP4を確認する。投稿UIの実表示は実際に見たときだけ確認済みとする。
