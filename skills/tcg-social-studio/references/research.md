# 商品を決める

商品の調査は**毎日、制作の最初に自動で行う。** 人に頼まれるのを待たない。きのうまでの候補を使い回さず、毎回その日の動きを調べ直してから、ネタ（商品と型の組み合わせ）を出す。

流れは「1. 今の動きを調べる → 2. 候補に足す → 3. ネタを出す（ネタに使う商品の価格は、5のとおりに先に読む） → 4. 人が選ぶ（`plan_approval` が `chat` のとき。`all` のときは出してそのまま制作へ） → 6. ネタの1文を決めて、制作へ」。

扱うカードゲームは `client.json` の `games`（空なら `["pokemon"]`。ワンピースカードも扱うなら `["pokemon","onepiece"]`）。入っていないゲームの商品は出さない。

## 1. 今の動きを調べる

次の5つを、毎回この順に開いて読む。読めなかったものは飛ばし、`01_調査.md` に「読めなかった」と書く。読めなかったものを、動きが無かったことにしない。

| 調べるもの | 開く場所 | 読むもの | 分かること |
|---|---|---|---|
| 発売の予定 | 各ゲームの公式サイトの商品情報（ポケモンカード公式、ワンピースカード公式） | これから35日以内に出る商品と、直近14日に出た商品。商品名・発売日・再販の知らせ | 新弾と予約の時期 |
| 同業者の動き | `client.json` の `reference_accounts` のうち、日本から海外へ売っているアカウントの、直近7日の投稿 | どの商品（セット）を出したか、予約・新弾・再入荷・値下がりのどれか、出している価格（数字と、箱の状態） | 業者が今売ろうとしている商品と、その価格 |
| 海外で売れたもの | PriceCharting の売れた記録（直近7日と30日）。eBay は機械からの読み取りを拒むので開かない | 売れた件数が多い商品、前より増えた商品、売れた値段 | 海外の買い手が今買っている商品 |
| 国内の値動き | カードラッシュ、スニーカーダンクなど国内の相場 | この7日で値が上がった・下がった商品。スニーカーダンクでは、成立した取引の数も読む（直近7日と、その前の7日） | 日本で動いた商品 |
| 聞かれた商品 | 表の「聞かれた商品」タブの直近14日の行 | 商品と件数、聞かれた質問、売買の場で動いている商品（「種類」の列で見分ける） | この相手の客が欲しがった商品、客が気にしていること |

同業者の投稿は、1投稿1行で表の「同業者の動き」タブに足す（列は[表の書き方](sheet.md)）。同じ投稿を2回書かない（アドレスで見分ける）。

「聞かれた商品」タブは人が書く。空でも止まらない。「種類」が `聞かれた質問` の行は、商品の候補には足さない。誰向けかを決めるとき、補助7（悩みから入る）の見出しを決めるとき、本文で先に答えることを決めるときに使う。

## 2. 候補に足す

調べて見つけた商品を、表の「商品の候補」タブに1商品1行で足す。「見た目」には商品の画像、「なぜ今か」には下の区分と根拠を書く。古い行は消さない。同じ商品が7日以内の行にあれば、新しい行を足さずに、その行の「なぜ今か」と価格を今日の内容に書き直す。

### 「なぜ今か」の区分

| 区分 | 当てはまる条件 | 根拠として書くもの |
|---|---|---|
| `新弾・予約` | 発売日の21日前から、発売後14日まで | 発売日と、今日が発売の何日前・何日後か |
| `同業者が出している` | 「同業者の動き」タブの直近14日で、2アカウント以上が出している | アカウント名と投稿日 |
| `聞かれた` | 「聞かれた商品」タブの直近14日に、種類が `聞かれた商品`（または空）の行がある | 件数と日付 |
| `売買の場で動いている` | 「聞かれた商品」タブの直近14日に、種類が `動いている商品` の行がある（売り手どうしの売買の場などで、人が見た動き） | 日付と、メモに書かれた内容 |
| `海外で売れ出した` | 海外で売れた件数が、この7日で多い、または前より増えた | サイト名、件数、期間 |
| `国内で値が動いた` | 国内の相場が、この7日で大きく動いた。または、国内の取引の数が、前の7日より増えた | 2つの時点の価格と日付。取引の数なら、2つの期間の件数 |
| `定番` | 上のどれでもないが、下の「売れた記録」の条件を満たす | 直近30日の件数 |

2つ以上に当てはまる商品は、当てはまる区分を全部書く（例：`新弾・予約／同業者が出している`）。

### 候補に入れる条件（売れた記録）

- **海外で、直近30日に、同じ条件で3件以上売れている。** 売り手が2者以上で、売れた日が複数日にまたがっていること。
- `新弾・予約` の商品は、30日の記録がまだ無い。次のどれかがあれば入れてよい：海外で予約・発売直後に売れた記録が1件以上／同業者が2アカウント以上、その商品を出している／公式の発売日が今日の前後7日以内（同業者が1アカウントでも、まだ誰も出していなくてもよい）。
- `聞かれた` と `売買の場で動いている` の商品は、海外で売れた記録が1件以上あれば入れてよい。
- 英語版の売れ行きを、日本語版の根拠にしない。国内の人気を、海外の根拠にしない。
- ランキング・SNSの再生数・出品の多さは、探すきっかけ。それだけでは候補に入れない。
- 取れなかった数字を 0 にしない。空欄にして、取れなかったと書く。

届かない商品は入れない。その日の在庫があるかどうかは、条件にしない。

## 3. ネタを出す

「商品の候補」タブの、「調べた日」が今日の行（今日書き直した行を含む）から、ネタを `client.json` の `plan_count` の数だけ作る（空なら5）。ネタ1つは「商品・誰向け・形式・型・なぜ今か」の組み合わせ。

### 選ぶ順

1. `聞かれた` の商品。
2. `新弾・予約` と `同業者が出している` の両方に当てはまる商品。
3. `新弾・予約`、`同業者が出している`、`売買の場で動いている` のどれかに当てはまる商品。
4. `海外で売れ出した`、`国内で値が動いた` の商品。
5. `定番` の商品。

同じ順の中では、根拠の数字が大きいもの、確かめた日が新しいものを先にする。

### 誰向けかを決める

**ネタごとに、誰に向けた投稿かを1つに絞って言い切る。** 「誰にでも」のネタを作らない。誰向けかが決まると、見せる商品・買う理由・最初の画面の文字が決まる。

| 誰向け | 向く商品 | 買う理由にするもの |
|---|---|---|
| これから売り始める人・予算が少ないリセラー | 少ない数から頼めるまとめ売り、パック、シングル | 予算に合わせて組める、再販しやすい |
| くり返し仕入れる店・リセラー・配信者 | BOX、ケース、まとめ売り、PSA | 回転が速い、補充しやすい、今日の価格 |
| 欲しい1枚を探すコレクター | シングル、PSA | 欲しい1枚だけ頼める、状態 |

- 表は例。「聞かれた商品」タブのメモ（国、数量、言われたこと）と、過去の行で問い合わせが来た案から、この相手の客に合う言い方に直してよい。
- 誰向けかは、英語で短く言える形にする（例：`For new resellers`、`For shops & resellers`、`For collectors`）。最初の画面の上の文字に入れる（[型カード](types.md)）。
- 出すネタの中で、誰向けを2種類以上にする。

### 組み合わせの決まり

- ネタどうしで商品を別にする。同じセットは、形が違えば2つまで（例：BOXの価格と、そのセットのシングル）。
- B 価格表のネタは、商品を3つ以上並べる。1つの商品だけの価格表にしない。この型だけは、ほかのネタの商品と重なってよい。
- 未開封BOXとまとめ売りを、ネタの半分以上にする。シングルかPSA鑑定品を1つ以上入れる。
- **`client.json` の `focus_products` に商品の種類が書いてあるときは、上の1行の代わりに、次のとおりにする。** ネタの半分以上を、そこに書かれた種類の商品にする。そこに `BOX` が無ければ、未開封BOXのネタは1つまでにし、型は補助1 値動き（相場の話題）にする。BOXの価格を売り込む型（A・B・D）にしない。
- `client.json` の `footage_folder` に、実写か、お客さんのレビューの画面があるときは、ネタの1つを型E（梱包と実績）にする（[素材を取ってくる](assets.md)）。
- 形式は、リール・カルーセル・画像がそれぞれ1つ以上入るようにする。残りは型に合う形式にする。
- 型（[型カード](types.md)）と合う商品を選ぶ。価格表の型なら複数の商品、単品の型なら絵の強いカードや人気のBOX。
- **`新弾・予約` と `同業者が出している` の商品は、日付と価格が変われば、毎日出してよい。** それ以外の商品は、「投稿」タブの直近3日に出していたら選ばない。
- 同じ商品・同じ数字・同じ型のネタは、14日以内に2回出さない。
- 当てはまる商品が少ない日は、数をそろえるために弱いネタを足さない。出せた数だけ出す。

ネタに使った行の「使った日」は、そのネタが作られたときに書く（選ばれなかったネタでは書かない）。

## 4. 人が選ぶ（`plan_approval` が `chat` のとき）と、全部作る（`all` のとき）

**`chat` のときは、制作に入る前に、ネタをチャットに出し、人が選ぶのを待つ。** 画像も動画も、選ばれるまで作らない。

**`all` のときは、ネタをチャットに出してから、選ばれるのを待たずに全部作る。** 人が止めたネタは作らない。直しの指示があったネタは、直してから作る。

### 出し方

**決まった形の箇条書きで出す。** 文章でつなげて書かない。1つの項目は1行。ネタとネタの間は1行あける。項目の名前と順番は、下の形から変えない。

最初に、今日のネタの一覧を1ネタ1行で書く（番号・商品・形式）。続けて、ネタごとに次の形で書く。

```text
■ ネタ1：30th CELEBRATION BOX（未開封BOX）
- 誰向け：くり返し仕入れる店・リセラー（For shops & resellers）
- 形式と型：カルーセル／B 価格表
- 価格
  - 国内：¥18,300（スニーカーダンクの一番安い出品・11/20）
  - 海外：$152（PriceCharting の売れた価格・11/20）
  - 見積もり：¥20,130（$126）
  - 同業者：@samurai_sword_tokyo_jp ¥17,200（11/17・シュリンクあり）→ こちらが ¥2,930 高い
- なぜ今か：同業者が出している／国内で値が動いた
  - 直近7日で3アカウントが投稿（@… 11/13、@… 11/14、@… 11/17）
  - 国内の一番安い出品が7日で −4.6%（¥19,180 → ¥18,300）
- 最初の画面の文字
  - 英語：For shops & resellers / 30th CELEBRATION — Price List Nov 20 / BOX ¥20,130 ($126)
  - 日本語訳：店・リセラーの方へ／30th CELEBRATION／11月20日の価格表／BOX ¥20,130（$126）
- 画像：https://（公式か、国内の販売サイトの商品画像のアドレス）
```

項目ごとの決まり：

- **誰向け**：誰に向けた投稿かを1つ。日本語と、かっこの中に、画面に出す英語（上の「誰向けかを決める」）。
- **形式と型**：形式（リール／カルーセル／画像）と、[型カード](types.md)のカードの名前。
- **価格**：1つの価格を1行で書き、かっこの中に「どこの・何の価格か（一番安い出品／売れた価格）・確かめた日」を入れる。「見積もり」の行は、`price_display` が `quote` のときだけ書く。価格を出さないネタは `- 価格：出さない（理由）` の1行にする。同業者が同じ商品に価格を出していれば、アカウント名・価格・日付・箱の状態と、こちらとの差を書く。出していなければ `- 同業者：価格を出している同業者なし` と書く。
- **なぜ今か**：1行目に区分。その下に、根拠を1つずつ行を分けて書く（数字・日付・アカウント名）。
- **最初の画面の文字**：英語と日本語訳を、行を分けて書く。「誰向け」の英語を入れる。
- **画像**：作るときに使う正規の画像（公式か、国内の販売サイトの商品画像。[素材を取ってくる](assets.md)の決まり）のアドレス。まとめサイトや個人の画像のアドレスを出さない。正規の画像がまだ見つかっていなければ、`- 画像：未取得（作るときに公式から取る）` と書く。

最後に、「作るものの番号を教えてください。直したいネタは、番号と直す内容を書いてください」と1回だけ聞く。調べて読めなかったものと、決まりに合わずに外した商品は、その下に箇条書きで短く書く。

### 出す前に確かめる

チャットに出す前に、ネタごとに次を確かめる。1つでも外れたら、直してから出す。直せなければ、そのネタは出さない。

- 価格は、すべて今日読んだもの。国内の価格は「今日買える一番安い出品」で、成約の平均ではない。
- B 価格表のネタは、商品が3つ以上並んでいる。
- A 日付入り価格と D 単品と価格のネタは、最初の画面の文字に金額が入っている（価格を出さないネタは、型をA・Dにしない）。
- 画像のアドレスが、公式か国内の販売サイトのもの。
- 同業者の価格の行がある（無ければ「なし」と書いてある）。
- 「誰向け」が1つに絞られていて、最初の画面の文字に入っている。
- 上の形の項目が、全部そろっている。

### 返事を受けたあと

- 選ばれた番号だけを作る。1つでも、全部でもよい。
- 直す指示があったネタは、直した内容をもう一度チャットに出し、よいと言われてから作る。商品を替える指示なら、その商品を1〜2のとおりに調べてから出す。
- 「これも足して」と商品を言われたら、同じく調べて、ネタとして出す。
- どれも選ばれなかった、または返事が無い：その日は作らない。催促を重ねない。次の日は、新しく調べ直したネタを出す。
- 選ばれたネタと、言われた直しは、`01_調査.md` に残す。
- `all` のとき：返事が無くても、出したネタを全部作る。人が後から止めたネタは、その時点で作るのをやめる。作ったネタは `01_調査.md` に残す。

`plan_approval` が `off`（または空）のときは、人に聞かない。選ぶ順の上から、`daily_set` の形式に合うネタを `daily_set` の数だけ自分で選んで作る。

## 5. 今日の価格を読む

ネタに使う商品ごとに、国内と海外の価格を今日開いて読む。きのう以前に調べた商品は、必ず読み直す。ネタを出す前に読み、選ばれてから作るまでに日付が変わったら読み直す。

**ネタに出す価格は、今日読んだものだけにする。** 今日読めなかった価格しか無い商品は、ネタに出さない（その商品の値が大きく動いているときほど、古い価格では見積もりが仕入れ値を下回る）。

価格差が消えていた、海外の売れた記録が無くなっていた、のどちらかなら、その商品は今日は使わず、候補の次の商品に替える。その行の「出典」欄に、今日見送った理由を書き足す。

### どこで何を読むか

| サイト | 読むもの | 読み違えやすい点 |
|---|---|---|
| PriceCharting | その商品の参考相場、売れた件数（sold・volume） | サイト独自の計算値。直近1件の売値ではない。 |
| TCGplayer | Market Price（最近の販売から出した指標）、言語・版 | Listed Median は出品側の数字で、Market Price とは別物。英語版の数字を日本語版に当てはめない。 |
| スニーカーダンク | 国内の掲載価格、成立した取引の履歴、商品画像 | 出品価格・取引価格・買取価格は別。表示価格と支払総額も違う。 |
| CardZ Marketcap | PSA 10 の販売額・最終販売日・鑑定枚数（pop） | 鑑定枚数が多いカードは値下がりしやすい。 |

読めないサイトがあれば、読めたサイトだけで成り立つ見せ方にする。取れなかった数字を 0 や「在庫なし」として扱わない。新しい有料の収集サービスは契約しない。

### 同じものどうしを比べる

比べる前に、両側で次をそろえる。1つでも違えば、別の商品として扱う。

- セット名と番号（BOXは型番）、言語、版
- 単品か、BOXか、ケースか。1単位に入っている数
- 状態、鑑定の有無と点数、包装（シュリンクの有無）
- 価格の種類（売れた価格か、出品価格か、参考相場か）と通貨

比べ方は3つある。混ぜない。

| 比べ方 | 何と何を比べるか | 気をつけること |
|---|---|---|
| 同じ商品の国内と海外 | 日本語版の同じ商品が、日本と海外でいくらか | いちばん基本。差額は「海外USD −（国内JPY ÷ 為替）」。 |
| 日本語版と英語版 | 同じ絵柄の、言語が違う2つの商品 | 別の商品どうしの参考値。番号は版ごとに確かめる。「値引き率」は出さない。画像は各版の原画像を使う。 |
| 同じ商品の過去と今 | 同じ商品・同じ市場・同じ価格の種類の、2つの時点 | 過去の記録が無ければ変化率を作らない。2点の間の折れ線を作らない。 |

為替は、今日の1ドルの円の値を読み、出典と時刻を控える。

### 自分の見積もり価格を決める（`price_display` が `quote` のとき）

価格を出す型で使う商品ごとに、今日の自分の価格を計算して `01_調査.md` に残す。

1. 今日読んだ国内の価格のうち、今日買える中でいちばん安い価格を元にする（出品価格。買取価格、過去の取引価格、成約の平均ではない）。
2. 元の価格 ×（1＋ `quote_markup_percent` ÷100）。10円単位に切り上げる。空なら 10。
3. 今日の為替でドルに直す。
4. その額が、海外で売れた価格より安いことを確かめる。安くなければ、その商品は価格を出す型に使わない（補助の型に回すか、商品を替える）。
5. **海外で売れた記録がまだ無い商品（発売前の新弾など）は、比べる相手が無いので、自分の価格を出さない。** 発売日と「予約の見積もりを受け付けています」（例：`Pre-order quotes open — DM "PRICE LIST"`）と頼み方で作る。型は補助2 告知を使い、この場合は「補助の型は1つまで」に数えない。価格表（B）に並べるときは、金額の所に `Pre-order — DM for quote` と書く。

例：国内 ¥15,600 × 1.10 = ¥17,160 → ÷155 = $111 ＜ 海外で売れた価格 $139 → 使える。

## 6. 買う理由と、してほしい行動を1文にする

見出しを作る前に、案ごとにこの1文を埋める。

> ［客］へ、［海外で売れている特定の商品］を、［今日確かめた得］を理由に見せ、［具体的な行動］をしてもらう。

- 「客」は、ネタで決めた「誰向け」。
- 「得」は、価格差、値下がり、選べる単品、まとめ買い、発売・予約の早さなど。リセラー向けなら、再販しやすい、回転が速い、予算に合わせて組める。どの商品にも当てはまるほめ言葉は得にならない。利益の額や「もうかる」を得にしない（[文章](copy.md)）。
- 「行動」は1つに絞る。DMなら「合言葉（`client.json` の `contact.keyword`）と、カード名・数量・届け先の国を送る」にする。リンクなら、どのページで何を見てほしいかまで決める。
- 価格差が小さい日は、価格差を得にしない。値動き、品ぞろえ、選べること、など別の得で作る。
- 「人気」「今がチャンス」と書くなら、その根拠の数字を画面か本文に入れる。

型ごとの組み立ての例：

| 型 | 流れ |
|---|---|
| 言語別の価格比べ | 同じ絵柄の2つの版 → それぞれの価格 → 日本語版を選ぶ理由 → 価格と在庫の相談 |
| 値動き | 同じ商品の2時点 → 下がった幅 → 前に見送った人にとっての得 → 今の条件の相談 |
| 選べる単品 | セットで買う負担 → 欲しい1枚だけ頼めること → 頼み方 |
| 店・配信者向けのまとめ | 使い道 → 種類と数量と内訳 → 条件を送って相談 |
| 予約・発売 | 商品と発売時期 → 受け付けていること → 商品と数量を添えて相談 |
| 悩みから入る | 客の悩み → そうなる理由 → 解決になる商品と頼み方 → 条件を送って相談 |

## 7. 残すもの

制作フォルダの `01_調査.md` に、案ごとに次を書く。

- 商品（セット・番号・言語・状態・単位）
- 国内と海外の価格、価格の種類、通貨、為替、読んだ日時、開いたページのアドレス
- 海外で売れた記録（サイト、件数か日付）
- 誰向けか
- なぜ今か（区分と根拠。調べた5つのうち、読めなかったもの）
- 上の「1文」
- 選んだ理由（表の「選んだ理由」欄に、ここから1〜3文を写す）

## 8. 書いてよいこと・言い切らないこと

- 書いてよい：国内や海外の市場の価格、売れた記録、値動き、「相談してください」「見積もりを出します」。
- 言い切らない：確かめていない在庫数、発送日、最安、利益。`price_display` が `market` のときは、市場の価格を「この値段で売ります」に書き換えない。`quote` のときに出してよい自分の価格は、上の計算で出した額だけ。
- 注意書きの定型文は、画面にも本文にも足さない。価格を見せる案だけ、いつの価格か（`market` のときは、どこの価格かも）を画面に入れる（[文章](copy.md)）。出典は `01_調査.md` と、表の「相場と出典」の欄に残す。
