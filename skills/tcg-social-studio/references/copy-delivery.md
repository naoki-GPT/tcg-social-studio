# 投稿文と納品

## 興味づけと問い合わせへのつなぎ方

制作目的がDM相談なら「興味を引く→動画内で答え・判断材料を示す→具体的な相談へ」を基本にする。確定販売価格・在庫数・発送日を投稿で約束しない場合、それらを毎回人に問い合わせて制作を停止しない。既知の対応範囲と相談先は使い、取引条件は問い合わせ後に確認する。

国内の仕入れ先・市場価格を使う比較では、出典・確認日・商品の言語／番号／状態／単位を制作記録で確認し、参考価格と当店の販売価格を区別する。投稿面の表示は下記「注釈を載せない」を適用する。未確認の送料や販売利益を埋めない。取扱条件を載せない投稿でも、画像・文章から確保済み在庫や確定納期を約束していないか点検する。

## 注釈を載せない

2026-11-01本人指定。動画のテロップ・画像の下部・Instagram/Facebookキャプション・日本語訳では、「当店の販売価格ではありません」「スニダンの状態別参考価格です」等の価格の断り書きを付けない。英語の「not our price / quote」「marketplace reference」や、出典・確認日・送料等を毎回並べる定型の注意書きも、自動で追加しない。本文の末尾や別スライドへ移して復活させず、訳を説明するチャットにも独自の※注釈を足さない。

出典URL・確認日時・価格種別・送料の扱い・比較条件は、sources、comparison.json、BRIEF等の制作記録に保持する。注釈欄をなくしても数値の確認を省かず、外部市場価格を未確認の自社売価として「この価格で販売」「送料込み」等へ書き換えない。商品・通貨・1枚／1BOX・状態A/C・日本／海外など、何を比べているかを示す短い見出しや項目名は通常の本文として設計する。利用者が個別に表示を求めた情報はその指示に従う。

訴求は価格差だけに固定しない。価格の意外性、仕入れ候補の比較、店舗の補充、販売単位の見落とし、商品探しの手間などから、対象客に合う切り口を選ぶ。根拠のある答えを後で見せる、商品や数字の一部を一時的に隠す、疑問形で始める演出も使う。答えは投稿内で回収し、比較条件を隠す仕掛けにはしない。

「最安」という語自体を一律に禁止しない。「この3候補で最安は？」のように確認した比較範囲と整合する問い・結果に使える。疑問形や演出でも、未確認の店頭最安・世界最安・自社最安を暗示する根拠にはならない。「この中で最安」は割安さや再販売利益と同じ意味ではない。範囲を広げず、具体的な数値・比較・見せる順番で強さを作る。

画面文とキャプションは一緒に設計する。実際の競合本文も参照し、友人と普段その商品の話をするような自然な言葉で、具体的なひと言と必要な条件、DMする理由をつなぐ。一般的な賛辞、毎回の自己紹介、同じ説明の反復は足さない。適切な問いや比較は仮説であり、実証済みの売上効果とは扱わない。

## 原稿

英語圏向けが標準。参考の問いかけ・欲しくなる理由・商品の見せ方を踏まえ、自然で短い英語を使う。最初から自己紹介や商品の仕様一覧にしない。利用者の国・言語指定を優先する。

1. 冒頭で買い手が気になる具体的な場面を示す。
2. 何を紹介し、どう役立つかを説明する。
3. 価格・版・状態・注文条件のうち必要なものを添える。
4. 名前や写真をDM、商品ページを見る等、行動を1つに絞る。

Instagramは短く直接的な商品訴求を使える。Facebookは投稿先・グループの条件を実際に確認し、客に合う背景説明を足す。過去案件の写真必須・値段禁止・投稿時刻・ページ名・グループURLを引き継がない。自分の売値を入れる場合は確認済みの価格・通貨・条件を使う。

例えば「欲しい1枚から」の訴求は、希望カードの名前か写真を送る → 日本側で候補を調べる → 注文前に在庫・状態・総額を確認する、という流れ。これは提供可能な業務が確認できている場合の例で、全利用者へ無条件に約束させない。

動画用の短い字幕と投稿本文は役割が違う。全文を動画へ詰め込まず、字幕は短く、本文で必要な条件を補足する。承認済み原稿を動画化する場合は、意味や約束を変えない。逐語保持指定なら文字列でも照合。

日本語訳は英語の条件・主語・約束と一致させる。英語より強い表現を訳で足さない。ハッシュタグは商品と客に合うものだけ。根拠のない最安・即納・必ず利益・在庫あり・人気No.1を追加しない。

画像の出典やAIによる場面制作は来歴として必ず記録し、表示が必要なら投稿本文へ反映。出典を書くだけで素材利用条件を満たしたと判断しない。機微な位置・カメラ情報は除去できるが、虚偽の撮影情報を付けない。

## 保存する一式

```text
制作フォルダ/
  00_投稿一式.md
  01_競合分析.md
  02_Instagram_英語.txt
  03_Instagram_日本語.txt
  04_Facebook_英語.txt
  05_Facebook_日本語.txt
  BRIEF.md
  accounts.json / posts.json / analysis.json
  assets_manifest.json
  sources/                  出典・取得記録・参考画面
  assets/                   原画像・生成原本・採用素材
  index.html / content.js    編集できる動画
  reel_v1.mp4 / cover.jpg / contact_sheet.jpg
  review.html
  checks/                   検品記録
```

静止画だけの指定ならMP4関連を完成画像へ置き換える。比較調査が小規模なら表をMarkdownへまとめてもよい。不要な空ファイルを形式のために量産しない。

`00_投稿一式.md` は何の投稿か、採用版、英文と訳、動画・画像、誘導先、参考、確認済み／未確認を1か所で読める構成。資料リンクだけを貼って終わらない。

`review.html` は冒頭で目的を説明し、完成動画、短い分析と実際の参考画像、場面一覧、投稿文へのリンクを載せる。初見で参考と自分の制作物を取り違えない。PC・スマホ幅で表示確認する。

## 最終確認

商品名・番号・版・数量、値段と確認日、本人が対応できること、行動案内、リンクを突き合わせる。字幕と両媒体本文で条件を変えない。参考から取り入れた点・変えた点をBRIEFへ。実測の再生数と将来の成果予想を混同しない。

完成ファイルを実際に開き、未取得・生成不可・素材条件未確認を具体的に伝える。問題のない制作まで停止させない。投稿準備完了、試作完成、公開済みを区別する。

投稿後の計測・成果分析は別スキル／別作業へ渡す。制作時は投稿を識別できる名前、対象客、商品、訴求、参考デザイン、DM案内をBRIEF等へ残す。公開後の投稿URL・公開日時・観測日時・数値は実際に提供されたものだけ追記し、未計測を0にしない。分析結果を次の制作に使い、競合分析や素材の変更だけで成果を保証しない。制作完了を分析や定期起動の実装完了と混同しない。
