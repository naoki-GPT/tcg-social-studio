# 完成判定と差し戻し

v2.0 / 2026-11-12。書き出せた、動画が再生できた、文字が切れていない、だけでは完成ではない。

## 制作前

1. 需要：対象客・商品条件・期間・根拠・候補比較がある。価格表やランキングだけで売れ筋判定していない。
2. 買い手の得：なぜ今これを買う／相談するかが具体的。価格差なら比較条件・費用・意味のある差を確認。
3. 行動：画面と本文と実導線がつながり、本文に送る内容／開く場所がある。
4. 参考：全枚／全編が保存され、文字とページ／時間の役割が分解済み。

足りない企画は候補変更・再調査。需要の弱さをデザインや強い形容詞で隠さない。

## 制作後

5. 全対応：元の全スライド、全カット、全テロップ、全効果に完成物側の対応がある。意図した差は理由・影響を記録。未再現は不合格。
6. 見た目：全ページを参考と並べ、レイアウト・文字・配色・商品面積・背景まで確認。動画は同期全編比較、切替前後1フレーム、動きの中間を確認。冒頭だけで合格にしない。
7. 内容：商品・価格・日付・英日・数量・単位・主語・CTAが一致。人気や販売条件の未確認の断定を入れない。
8. 技術：全ファイル、解像度・比率・尺・画像読込・終端・音声・文字切れを検査。実MP4で止まる動きは未実装。

`production-contract.json`に根拠と確認ファイルを指定する。`validate_production.py`は欠落・期限・全枚対応・未解決差分を検出する。チェック欄をtrueにするだけで検品した扱いにはしない。並べた画像／同期比較と、どこを見て何を直したかを保存する。自動判定は完成要件の構造チェックで、内容の正しさや質の保証ではない。

不合格の理由は具体的にする。「弱い」ではなく「本文にDMで送る内容がない」「英語版の販売数しかなく日本語版需要を確認していない」「元9枚のうち8枚未対応」「0.80秒の字幕が1.20秒にずれた」のように示す。

## 最終状態

- **分析済み**：参考の全文と設計が揃った。新作はまだ。
- **試作**：出力はあるが需要・事実・再現・利用条件に未解決あり。
- **制作完了**：全要件を確認した完成物・本文・記録が揃った。公開承認は別。
- **公開済み**：実公開URLと結果を照合した場合のみ。
