# tcg-social-studio 2.2.0

この配布版は外部収集サービスの専用コード・手順を削除し、Museから全素材を受け取る構成です。[素材の受け渡し](references/media-input.md)から入力を用意します。既存の制作プログラムを使い、Museとの連携はリポジトリ最上位の引き継ぎ書に従って整備します。

2026-11-13更新。第1工程「案件の前提確認」を独立した `tcg-social-intake` に分けました。配布セットの `tcg-social-studio` と `tcg-social-intake` を同じskillsフォルダに置きます。元のスキルだけでは新しい入口がそろいません。

2.0.0で、商品を売る理由と、参考を再現する手順・道具を作り直しました。Grokbot版1.9から参考ごとの作り方カードと描画の仕組みを取り込み、需要の自動点数判定は採用していません。

使うAIにこのフォルダの `SKILL.md` を読ませ、案件の資料・台帳・保存先を指定します。案件の前提確認 → 商品の選定 → 買い手の得 → DMや商品ページへの行動 → 参考全枚/全編の分析 → 制作 → 比較検品の順に進みます。相場表だけで商品を選ばず、雰囲気だけ似せた汎用テンプレートを完成にしません。

例：「今回の対象客は海外のカード店。素材台帳のREF-005を全9枚で再現する。現在の需要と買う理由が成立する商品を調べ、英語本文と日本語訳、完成画像、参考との全枚比較まで作って。参考の全素材はMuseで用意し、ブラウザー操作なし。」

既存の台帳や商品条件が分かっていれば聞き直しません。古い投稿価格・競合の発送実績・競合在庫を自社の事実として流用しません。需要が足りない候補は別候補を調べます。

第1工程だけ試す例：「$tcg-social-intake を使って、共通の試作1企画の前提を整理して。今回は第1工程まで。商品選定には進まない。」

この工程では前提表・根拠・未確認事項・次工程の指示をローカルへ保存します。Python標準ライブラリだけで検査でき、外部収集サービスの接続は不要です。第2〜7工程の独立スキル化は、各工程を実際に進めてから行います。

## 初回の準備

[利用環境](references/setup.md)に従い、必要な接続と保存先を確認してください。画像生成等の利用環境は配布先で確認します。秘密鍵・APIキーは同梱しません。

道具を使うPCでは、このフォルダで次を実行します。既存の依存部品を使う設定もsetup.mdにあります。

```powershell
python -m pip install -r requirements.txt
npm install
node scripts/check_env.mjs
```

全フレーム解析を使うときは追加で `python -m pip install -r requirements-analysis.txt`。参考はMuseから受け取り、[素材入力](references/media-input.md)の形式で全ファイルを取り込みます。元の枚数・順番・全編を実物で照合します。

## 同梱するもの

- 需要選定・訴求分析・全参考分解・完成判定の手順と記録例。
- 19型の目的分類、[実物を確認した参考索引](references/verified-reference-map.md)、参考ごとの作り方カード。
- 全子画像/動画の取得、全フレーム差分と動き解析、画像・無音動画の出力、全枚/同時刻比較、完成前チェックの道具。
- REF-005の実測配置から作る専用HTML。原書体・背景模様は近似であり、完成済みの完全コピーではありません。

参考の原画像・動画、最新価格、顧客情報、相手PCの接続は同梱しません。案件の制作フォルダへ原本を保持します。完成判定には全出力を実際に開いた検品が必要です。公開・予約投稿・送信は別の指示で行います。

以前渡したZIPや別フォルダは自動更新されません。今回の親スキルは2.2.0、前提確認スキルは1.0.0です。配布セットには両方を含めています。[検証記録](VALIDATION.md)を参照してください。
