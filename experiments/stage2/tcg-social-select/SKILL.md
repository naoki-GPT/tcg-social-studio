# 第2工程：需要に基づいて商品を選ぶ

版：1.0.0／2026-11-13。**その客に今需要があり、買う理由を説明できる商品を選ぶ。** 完了は選定記録と次工程への引き渡しまで。工程ごとの依頼では本文・画像・動画を作らない。

## 前提を受け取る

第1工程の `01_intake.json` と検査結果を読む。案件、客、国、主な行動、商品範囲、企画数、禁止された資料を引き継ぐ。前提が不足する場合は `$tcg-social-intake` で必要部分を整理する。すでに決まった条件は再質問しない。

「次へ」はこの工程の実行指示であり、残り全工程の一括実行ではない。仮置きは仮置きのまま明示する。店頭補充とネット再販など対象を絞った場合は、変更理由と影響を引き渡し記録へ残す。特定店の在庫・売価・顧客実績を共通試作へ混ぜない。

## 調査条件を決める

必読：[証拠・集計・価格の扱い](references/evidence-guide.md)。比較する前に、期間、地域の判断方法、状態、単位、使う価格の種類、買い手の最低限の得を記録する。売値や費用が未定なら、成立に必要な仕入れ総額を逆算する。仮の採算条件を市場の標準や確認済みの利益と表現しない。

基本は直近30日と直近7日。対象市場の当日が途中なら除き、掲載日付のタイムゾーンが不明ならそのまま記録する。取得日を成約日にしない。調査日時・データが表す時点・掲載期間を別々に残す。

同じ購入用途の候補を通常3〜5点程度比較する。指定商品があれば別物へ勝手に替えず、その商品の採用可否を検証する。候補数は取得件数や制作企画数と別。過去に却下された商品は新しい根拠と欠点の解消なしに戻さない。

## 公開情報を取得・照合する

- スニダン：期間の分かる取引数資料で候補を発見し、商品ページで条件と現在の調達参考価格を確認する。人気順・出品数・ハート数を成約数にしない。
- eBay：言語・セット・番号を絞った販売済み情報。出品者、日付、個別ID、状態、単品か、価格交渉の有無を確認する。国フィルター指定後も各行の所在地を再確認する。
- TCGplayer：日本語版の該当番号と公開成約・公式集計を探す。英語版やBOXの売上を日本語版シングルの根拠にしない。
- Amazon日本：同一商品の購入数表示や販売順位が取得できる場合に使う。単品・パック・鑑定品の混入を確認する。順位から販売枚数を逆算しない。

4サイトの確認結果または取得できない理由を記録する。全候補が全サイトにあることは求めない。自社の受注・商品指定DMはアクセス許可がある場合だけ補強材料にできる。触らない表を読む代替として、その保存済みコピーを使わない。

ブラウザー操作禁止ならMuse側のWeb検索・通常のHTTPと許可済みの手元資料を使う。取得不能を0件・0円にしない。ログイン用Cookieや顧客資料を外部の収集サービスへ送らない。

受け取った結果は検索条件どおりとは限らない。各行の国・言語・番号・状態・数量を照合し、値下げ交渉の実額不明と配送先不明の送料を分ける。収集機能の成功表示だけで採用せず、元資料の内容を読む。

## 候補を比較して採否を決める

原本を制作フォルダの `sources/` に保存し、[記録ひな形](assets/selection.template.json)に条件・根拠・欠測・採否を記入する。一次の販売済み検索、元出品本文、二次集計を分ける。二次サイトの同じeBay出品を別の独立した根拠に数えない。

同条件の初期目安は、独立ID3件・出品者2者・複数日。件数だけで「人気」「確実に売れる」としない。取得上限に達した標本同士を月販ランキングにしない。出品者の偏り、古い高値、直近の値下がり、競合の供給も確認する。

採用理由は、①どの客の需要をどの証拠で確認したか、②買い手にどんな得があるか、③他候補よりこの企画に適する理由、をつなぐ。根拠不足なら追加調査または別候補へ。全部不十分なら `selected_id: null` として不足を残す。「注目カード」への言い換えで販売目的の選定を通さない。

仕入れ代だけの差額は利益ではない。送料・税・決済・仕入れ代行・販売費用・買い手が残したい金額を含めて考える。条件不明なら「送料等を含む見積りが○ドル以内なら検討できる」のように成立条件を残し、自社がその金額で売れると約束しない。同等品質未確認なら「同条件で○%安い」は保留する。

## 次工程へ渡す

```powershell
python <このスキルの場所>/scripts/check_selection.py <制作フォルダ>/02_selection.json --out <制作フォルダ>/02_selection_check.json
```

検査はファイルの存在とハッシュ、期間・商品条件・重複・価格種別・引き渡し条件の確認補助。人気や文章の質を自動採点しない。根拠本文と採否理由を読み直す。

`02_selection.md` に候補比較表、採用商品、具体的な買う理由、使える事実、まだ言えないことをまとめる。`02_selection.json` と根拠原本・観測行・検査結果も残す。第3工程には商品識別、対象客、需要の証拠、見積り条件、主な行動、使用可能な主張を渡す。

`ready_for_copy: true` は訴求設計に進める意味。販売条件が未確認のまま広告を公開できる意味ではない。工程ごとの依頼ではここで止め、確定事項と条件付きの判断をユーザーに示す。通常の全制作依頼は内容照合後に親の `$tcg-social-studio` 第3工程へ進む。
